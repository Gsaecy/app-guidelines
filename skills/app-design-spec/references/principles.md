# 设计原理（principles.md）

> 规范回答「用多少」，原理回答「为什么」。评审时用原理判断「这样改是否有依据」。

## 一、格式塔原则

| 原则 | 结论 | 落地做法 |
|---|---|---|
| 接近性 Proximity | 距离近 = 一组 | 同组间距 ≤ 组间间距的 1/2；同组 16，组间 24–32 |
| 相似性 Similarity | 外观像 = 一类 | 同类操作同色同形；危险操作换色 + 图标 |
| 闭合性 Closure | 大脑补全形状 | 图标可留缺口；不必画满边框 |
| 连续性 Continuity | 视线沿线条移动 | 表单/列表左对齐成一条线 |
| 图底关系 Figure/Ground | 区分主体与背景 | 模态用遮罩；内容层对比不低于背景 |
| 共同区域 Common Region | 同容器 = 一组 | 卡片圆角 12–20 + 内边距 16–24 |

## 二、交互定律

### Fitts 定律
- 公式：ID = log₂(2D / W)，移动时间随距离增加、随目标尺寸减小而增加。
- 落地：热区 ≥ 44×44pt（iOS）/ 48×48dp（Android）/ 32×32px（桌面鼠标）；主按钮高 40–50；危险操作不要贴边或紧邻高频按钮。

### Hick 定律
- 公式：RT ≈ a + b·log₂(n+1)，选项每翻一倍约多 1 bit 决策时间。
- 落地：一级导航 3–7 项；下拉 ≤ 12 项，更多用搜索；常用项前置并给默认值。

### Doherty 阈值
- ≤ 400ms：感觉即时，可保持专注。
- 1s 内：流畅，无需提示。
- > 10s：用户会切走，必须给进度、剩余时间与取消。
- 落地：按压反馈 ≤ 100ms；页面切换 240–320ms；长任务分阶段反馈。

## 三、认知与记忆

| 效应 | 结论 | 落地 |
|---|---|---|
| 米勒定律 | 工作记忆约 4±1 块 | 导航 ≤ 7 项；表单分步；数字分组 |
| 冯·雷斯托夫 | 不同者最易记 | 一屏只让一个元素跳出来（主 CTA / 错误） |
| 序列位置 | 首尾记得牢 | 重要项放首尾；长列表中段给搜索 |
| 峰终定律 | 由峰值与结尾决定 | 成功态明确；错误恢复体验优先 |
| 认知负荷 | 变量越少完成率越高 | 默认值、智能填充、记住上次选择 |
| 渐进披露 | 先必要后展开 | 高级选项进「更多」；首次只教一件事 |

## 四、约定与心智

- **雅各布定律**：用户大部分时间在别的产品上 → 沿用平台控件与手势。
- **特斯勒定律**：复杂度守恒 → 系统承担（预设/自动化），别塞给用户。
- **美学-可用性效应**：好看会被认为好用，但只在小问题上；可用性缺陷不会被美观掩盖。
- **心智模型**：齿轮=设置、垃圾桶=删除；新概念必须给可见解释。
- **信息架构**：用用户词，不用内部术语；一级分类 ≤ 7。
- **最小惊讶**：同一图标同一含义，同一手势同一行为。

## 五、原理 → 数值映射

| 原理 | 结论 | 规范数值 |
|---|---|---|
| Fitts | 越大越近越快 | 热区 44/48/32；主按钮 40–50 |
| Hick | 选项越多越慢 | 导航 3–7；下拉 ≤ 12 |
| Doherty | 400ms 反馈闭环 | 悬停 120–180ms；页面 240–320ms |
| 米勒 | 4±1 块 | 表单分步；卡片 ≤ 3 层信息 |
| 接近性 | 间距即分组 | 4 的倍数；同组 16 / 组间 24–32 |
| 共同区域 | 容器即分组 | 卡片圆角 12–20 + 内边距 16–24 |
| 峰终 | 结尾决定记忆 | 成功页/完成动画；错误给下一步 |
| 雅各布 | 沿用约定 | Windows 4/8 圆角、sentence case；iOS 44pt |

## 六、评审时怎么用

1. 先问「这条改动解决了哪个原理层面的问题」，答不出就是审美偏好。
2. 层级问题优先用格式塔判断：是不是间距没拉开、容器没画清。
3. 转化问题优先用 Hick / Fitts：选项太多或目标太小。
4. 体感问题优先用 Doherty：反馈太慢或动画太长。
